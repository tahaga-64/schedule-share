# Schedule Share

同じ予定表を全員で使う、設置場所を選べるWebアプリです。既存のReact画面を再利用し、予定・申請・案件・設定・履歴を同梱サーバーのSQLiteへ保存します。

Google / Firebase / Cloudflareのアカウント、外部DBの契約、クラウドAPIキーは不要です。GitHubはコードの配布元として使います。取得・インストール後の通常利用にGitHub接続は必要ありません。

## 全員で1つの予定表を使う仕組み

~~~text
GitHubのコード → 共有用サーバーで1つ起動 → 1つのSQLite
                          ↑       ↑       ↑
                       利用者A  利用者B  利用者C
~~~

共有用サーバーのURLを全員が開きます。利用者全員が個別にサーバーを起動する必要はありません。別々の場所で各自起動すると、それぞれ別の保存先になります。Git cloneはプログラムの複製であり、予定データの同期機能ではありません。

あなたのPCを停止しても使い続けるには、本番を常時稼働サーバーへ置きます。特定のクラウドには固定しません。サーバーの設置先・稼働費用・契約と復旧の管理は必要であり、このソフトを配布しただけでなくなるものではありません。ソフトの無料利用とサーバー代は別です。

## クローンして起動

Node.js 24以上を用意します。リポジトリURLは公開後の実際のURLへ置き換えてください。この配布物は公開前の状態です。

~~~sh
git clone <リポジトリURL> schedule-share
cd schedule-share
npm ci --ignore-scripts
npm run build
npm start
~~~

http://localhost:3217/ を開きます。既定はこの端末だけで試すモードです。外部サービスの登録や環境ファイルの作成は不要です。インストール時はnpmから依存パッケージを取得します。通常稼働時は同梱のフォントも含めて同じサーバーから配信します。

## 全員で共有する配置

1. 常時稼働するサーバーへこのコードを配置する。
2. 以下のコマンドで共有モードを起動する。
3. HTTPSの共通URLを用意し、編集用/閲覧用リンクを配る。

~~~sh
node server/index.mjs --host=0.0.0.0 --access=link
node scripts/links.mjs --base-url=https://schedule.example.com/
~~~

example.comは説明用です。実際の配置先へ置き換えます。リンクを知る人がその権限でアクセスできます。編集用リンクを公開リポジトリや一般公開ページへ置かないでください。ログインアカウントは作りません。閲覧用リンクではサーバーも更新を拒否します。

[配置・永続保存・引越しの手順](docs/DEPLOYMENT.md)に、HTTPSの接続、データフォルダ、バックアップ、Dockerの方法を記載しています。

## チーム名簿を変える

config/team.jsonのmembersを自分たちの名簿へ変更し、npm run buildでビルドし直します。leadMembersはその名簿の中から選びます。配布物の21人は「メンバー01」のような例です。実在の社員名・本番の予定・履歴・案件は含みません。

予定・申請・案件・研修ラベル等の通常の編集はアプリの画面で行います。データフォルダを保持すれば、ビルドし直しても既存の予定を初期化しません。名前がデータの識別子なので、既存メンバーの改名は別名として扱われます。改名時のデータ引継ぎはバックアップを取って計画してください。

## Docker

~~~sh
docker compose up -d --build
docker compose exec schedule node scripts/links.mjs
~~~

Composeはlocalhost:3217へ公開し、SQLiteと共有リンクの鍵をschedule-dataボリュームへ保存します。外部公開時はHTTPSのリバースプロキシを配置します。この作業環境にはDockerがなく、Dockerイメージの実ビルドは未確認です。Node.jsでの起動とテストを検証対象にします。

## 検証

~~~sh
npm run lint
npm test
~~~

通信を使う保存・同時更新・変更通知・申請承認・閲覧制限・再起動・JSON復元のテストと、既存申請処理の回帰テストを含みます。ビルド後にテストしてください。

## 制約

- 共有データの保存先は1つ必要です。共有サーバーまで不要なアプリではありません。
- 1つの保存先につき1サーバープロセスで動かします。SQLiteファイルを複数サーバーから直接共有しません。
- PWAとしてホーム画面に追加するための対応は、この配布版にはまだ含みません。
- 実ブラウザでの全画面操作とDockerでの稼働は、別途確認が必要です。
- 既存の公開アプリや本番データは変更・移行していません。
